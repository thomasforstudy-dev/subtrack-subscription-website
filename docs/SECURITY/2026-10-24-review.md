# AllOutFree — security and bounded local load review

Date: 24 October 2026. **Report only: no application fixes, merge or deployment.**

## Safe / needs attention

**Observed safe in this scope:** no cross-account data leak; no HTTP 500, connection failure or process crash in either load run; CSRF protection and the tested rate limits worked. The preview fetcher rejected private destinations, including the metadata IP.

**Needs attention, unresolved:** private-page cache protection is incomplete; private-IP bookmarks can still be saved despite the requested rejection policy; general HTML security headers are missing. Static review also found that the limiter's `MAX_KEYS` is an expiry-cleanup trigger, not a hard bound on active keys. None of these findings is evidence of successful database entry or cross-account access.

### Query audit notes

Avoid flagging every grep match as a vulnerability:

- `subscriptions.own_or_404`, `bills.own_bill_or_404` / `own_document_or_404`, `links._own_link_or_404`, `bill_review.own_job_or_404` / `own_draft_or_404` and token revoke filter the current owner before returning an object.
- `api_tokens.find` identifies a token by its cryptographic hash; `touch` and revoke's follow-up UPDATE use that already-validated object. They are not arbitrary-ID entry points.
- `bill_review.show` loads the associated bill by ID after obtaining an owned draft; `forecast` reads `BillLine` rows only for IDs from the current user's bills. These are indirect ownership guards; explicit filters would improve defense in depth if those functions change.
- `User` lookup for login/session loading and one-time token authentication cannot initially filter by an already logged-in user. Session loading verifies its fingerprint; admin listing is protected by `admin_required`.
- Job/reminder workers intentionally operate across accounts internally; reminder delivery also checks subscription/user ownership. Fingerprint migration is internal startup/CLI work. Reviewed raw SQL is static schema/migration/diagnostic SQL, not concatenated user input.
